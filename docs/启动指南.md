# pomelo-ai 启动指南

本文档帮你从零把 pomelo-ai 跑起来,并完成一次完整的「上传文档 → 提问 → 得到带引用的流式回答」。

---

## 0. 架构与端口一览

| 组件 | 端口 | 说明 |
|---|---|---|
| pomelo-ai 应用 | **8080** | Spring Boot 主服务 + Web 界面 |
| MySQL | 3306 | 库 `pomelo_ai`(自动创建),root/root |
| Redis | 6379 | 会话历史 + 鉴权 token |
| Milvus | 19530 / 9091 | 向量库 / 健康检查 |
| **Attu** | **3000** | Milvus 图形化管理台,管理 Collection / 向量 |
| MinIO | 9000 / 9001 | Milvus 对象存储 / 控制台 |
| etcd | 2379 | Milvus 元数据(容器内部) |
| Ollama | 11434 | 大模型 + 嵌入模型 |
| MinerU(可选) | 8000 | 文档解析,默认关闭 |

> 依赖方向:`api → service → repository → domain`,`core` 与 `common` 被各层复用。详见 README 目录结构。

## 1. 环境前置要求

| 软件 | 版本 | 核对命令 |
|---|---|---|
| JDK | **21**(LTS) | `java -version` |
| Maven | 3.8+ | `mvn -v` |
| Docker | 24+ | `docker --version` |
| Docker Compose | v2+ | `docker compose version` |
| Ollama | 0.1.30+ | `ollama --version` |

> Maven 如需走国内镜像,在 `~/.m2/settings.xml` 配置华为云/阿里云仓库(项目 pom 不绑定私有仓库)。

## 2. 第一步:启动基础设施(MySQL + Redis + Milvus)

> ⚠️ **国内 Docker 镜像拉取加速**:由于 2024 年起国内公共 docker.io 镜像源大批关停,
> 本项目 `docker-compose.yml` 已将所有 docker.io 镜像改为走**渡渡鸟镜像同步站**同步到的
> 华为云 SWR 仓库(`swr.cn-north-4.myhuaweicloud.com/ddn-k8s/`),支持匿名 pull,无需 docker login。
> 若某 tag 返回 `not found`(渡渡鸟只同步了部分 tag),去 https://docker.aityp.com 搜索同镜像可用 tag。

在项目根目录执行:

```bash
docker compose up -d
```

它会拉起 5 个容器:`pomelo-etcd`、`pomelo-minio`、`pomelo-milvus`、`pomelo-mysql`、`pomelo-redis`。

**验证:**
```bash
docker compose ps
```
看到 5 个容器都在 `running`。Milvus 首次启动较慢(`start_period: 90s`),给它约 1~2 分钟:

```bash
# Milvus 健康检查
curl http://localhost:9091/healthz      # 期望: OK
# MinIO 控制台(浏览器)
# http://localhost:9001   账号 minioadmin / minioadmin
```

> MySQL 库 `pomelo_ai` 由 compose 的 `MYSQL_DATABASE` 自动创建;应用启动后 JPA(`ddl-auto: update`)会自动建表,无需手动执行 SQL。

## 3. 第二步:启动 Ollama 并拉取模型

```bash
# 启动 Ollama 服务(若尚未常驻)
ollama serve

# 拉取对话模型(约 4.7GB)
ollama pull qwen2.5:7b

# 拉取嵌入模型(768 维,约 270MB)
ollama pull nomic-embed-text
```

**验证模型可用:**
```bash
# 对话
ollama run qwen2.5:7b "你好,用一句话介绍自己"
# 嵌入
curl http://localhost:11434/api/embeddings -d '{"model":"nomic-embed-text","prompt":"测试"}'
```
后者返回一个 768 维浮点数组即正常。

> GPU 用户:Ollama 会自动用 GPU;纯 CPU 也能跑,只是生成较慢。`qwen2.5:7b` 在 16GB 内存机器上可跑。

---

## 4. 第三步(可选):启动 MinerU 解析服务

项目默认用 **PDFBox / POI 本地解析**(已内置,开箱即用)。若要更好的 PDF 富文本/表格/公式解析,可启用 MinerU 4.0:

```bash
pip install "mineru>=4.0,<5"
mineru server start          # 默认 http://localhost:8000
```

然后在 `application.yml` 打开开关:
```yaml
pomelo:
  mineru:
    enabled: true
```

> MinerU 不可用时,系统自动回退本地解析器,不影响主链路。

## 5. 配置说明

`src/main/resources/application.yml` 关键项(均带注释,按需调整):

```yaml
pomelo:
  ollama:
    base-url: http://localhost:11434     # Ollama 地址
    chat-model: qwen2.5:7b               # 对话/重排/Self-RAG 判断模型
    embed-model: nomic-embed-text        # 嵌入模型
    embed-dimension: 768                 # 必须与模型一致
  milvus:
    host: localhost
    port: 19530
    collection-prefix: pomelo_           # 每个 KB 的 collection 名前缀
  chunk:
    size: 500                           # 切块字符数
    overlap: 50                         # 重叠
  rag:
    top-k: 8                            # 向量召回数
    rerank-top-k: 4                      # 重排后进入上下文数
    max-iterations: 3                    # Self-RAG 最大迭代
  auth:
    username: admin                     # 默认登录账号
    password: admin123
    token-ttl-minutes: 720              # token 有效期 12 小时
```

> 若 MySQL/Redis/Milvus 不在本机,改 `spring.datasource.url`、`spring.data.redis.host`、`pomelo.milvus.host` 即可。

## 6. 第四步:构建与运行

```bash
# 编译(首次会下载依赖,约 2~5 分钟)
mvn clean compile -DskipTests

# 启动应用(前台,看日志)
mvn spring-boot:run

# 或后台运行 jar(需先打包)
mvn clean package -DskipTests
java -jar target/pomelo-ai-*.jar
```

启动成功标志(日志):
```
Tomcat started on port 8080 (http) with context path ''
Started PomeloAiApplication in X.XXX seconds
```

**验证服务存活:**
```bash
curl http://localhost:8080/actuator/health   # 期望: {"status":"UP"}
```

打开浏览器访问 **http://localhost:8080** ,用 `admin / admin123` 登录。

## 7. 端到端操作流程(含 curl 示例)

### 7.1 登录获取 token
```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' \
  | grep -o '"token":"[^"]*"' | cut -d'"' -f4)
echo $TOKEN
```

### 7.2 创建知识库
```bash
KB=$(curl -s -X POST http://localhost:8080/api/kb \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"产品手册","description":"演示用"}' \
  | grep -o '"id":"[^"]*"' | head -1 | cut -d'"' -f4)
echo "知识库ID: $KB"
```
> 创建时会自动在 Milvus 建一个 768 维 Collection(HNSW + 余弦距离)。

### 7.3 上传文档(自动触发入库流水线)
```bash
curl -s -X POST "http://localhost:8080/api/doc/upload/$KB" \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@./你的文档.pdf"
```
> 上传后异步执行:解析 → 切块 → nomic 向量化 → 入 Milvus。状态机:`PENDING → PARSING → CHUNKING → EMBEDDING → INDEXING → SUCCESS`。

查看文档状态:
```bash
curl -s "http://localhost:8080/api/doc/list/$KB" -H "Authorization: Bearer $TOKEN"
```
等到 `status: SUCCESS` 再提问(可多传几个 txt/pdf/docx)。

### 7.4 提问(SSE 流式)
```bash
curl -N -X POST http://localhost:8080/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"kbId\":\"$KB\",\"message\":\"文档里说了什么?\"}"
```
输出形如:
```
event:token
data:根据
event:token
data:文档
...
event:done
data:{"sessionId":"...","answer":"...","citations":[{"docName":"...","page":3,"snippet":"..."}]}
```

非流式问答(直接拿完整答案):
```bash
curl -s -X POST http://localhost:8080/api/chat/ask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"kbId\":\"$KB\",\"message\":\"总结一下\"}"
```

### 7.5 多轮对话
同一 `sessionId` 继续发问即可实现多轮(历史走 Redis 滑动窗口):
```bash
curl -N -X POST http://localhost:8080/api/chat/stream \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"kbId\":\"$KB\",\"sessionId\":\"上一步返回的sessionId\",\"message\":\"针对前面提到的第一点再展开说说\"}"
```

## 8. Web 界面使用

浏览器打开 http://localhost:8080 ,登录后:

1. 左侧选择知识库 → 点「上传文档」选文件
2. 等待右侧文档列表状态变 `SUCCESS`
3. 底部输入框提问,回车发送
4. 回答逐字流式出现,下方展示引用来源卡片(文档名/页码/片段)

> 这是内置极简测试页(`static/index.html`),用于端到端验证。如需正式前端,见 README 的 Vue3 TODO。

## 8.1 Milvus 图形化管理台（Attu）

Attu 是 Milvus 官方管理工具（v3.0.0），用于可视化查看/管理向量集合(Collection)。

浏览器打开 **http://localhost:3000** ，打开即进入（本地开发已关闭认证）。

左侧连接列表已预填 `milvus:19530`（由 `MILVUS_ADDRESS` 注入），点击即连上本服务 Milvus。

连上后可做：
- **Collection 管理**：查看每个知识库的 collection(`pomelo_*` 前缀)、schema、索引(HNSW)、向量维度(768)
- **数据查询**：按向量相似度检索、按过滤条件查询分区
- **向量化测试**：输入一段文本，直接看检索结果片段(调试检索召回率很方便)
- **统计监控**：行数、索引大小、存储占用
- **AI Agent**：v3.0 新增，自然语言管理 Milvus（需配 LLM API）

> Attu 连接地址用容器内网名 `milvus`（compose 服务名），不是 `localhost`——因为 Attu 自己也在 Docker 网络里，`localhost` 指的是它自己的容器。
> 生产环境如需登录认证，在 compose 去掉 `ATTU_AUTH_MODE=none`，设 `ATTU_ADMIN_USER` / `ATTU_ADMIN_PASSWORD`。

## 9. 常见问题排查

### Q0: `docker compose up` 拉取镜像失败 / `not found`
本项目 compose 已将镜像改为走渡渡鸟(华为云 SWR)前缀。若某 tag 返回 `not found`:
```bash
# 1) 去渡渡鸟搜索该镜像的可用 tag
#    https://docker.aityp.com  (搜索框输入镜像名)
# 2) 或用 docker manifest inspect 探测同镜像其他 tag
docker manifest inspect swr.cn-north-4.myhuaweicloud.com/ddn-k8s/docker.io/milvusdb/milvus:v3.0.0
# 3) 改 docker-compose.yml 里的 image tag 后重试
```
> 渡渡鸟只同步热门 tag,冷门 tag 可能没有。`quay.io` 镜像(etcd)可直连,无需走渡渡鸟。

### Q1: `mvn compile` 下载依赖很慢 / 超时
配置 `~/.m2/settings.xml` 走国内镜像:
```xml
<mirror>
  <id>huawei</id>
  <mirrorOf>central</mirrorOf>
  <url>https://mirrors.huaweicloud.com/repository/maven/</url>
</mirror>
```

### Q2: Milvus 连接失败 / 健康检查不过
```bash
docker logs pomelo-milvus --tail 50
curl http://localhost:9091/healthz
```
Milvus 首次启动需 90s+,确认容器 `healthy` 后再启动应用。若 `9091` 未映射或被占用,检查 19530/9091 端口占用:
```bash
netstat -ano | findstr "19530 9091"
```

### Q3: Ollama 调用超时 / 模型未找到
```bash
ollama list                    # 确认 qwen2.5:7b 和 nomic-embed-text 已下载
curl http://localhost:11434/api/tags   # Ollama 存活检查
```
嵌入/生成较慢时,调大 `pomelo.ollama.timeout-seconds`(默认 120)。CPU 跑 `qwen2.5:7b` 首次加载模型需数十秒。

### Q4: 文档上传后一直 `EMBED_FAILED`
多为 Ollama 嵌入模型未拉取或超时。看应用日志里 `文档入库失败` 堆栈。确认 `nomic-embed-text` 可用,且 `embed-dimension: 768` 与模型一致。

### Q5: 提问返回「根据现有知识库内容无法回答」
说明检索片段与问题相关性不足。可能原因:文档还在入库中、切块过大/过小、问题与文档措辞差异大。可调 `pomelo.rag.top-k` 增大召回,或检查文档状态是否 `SUCCESS`。

### Q6: 端口冲突
默认 8080 / 3306 / 6379 / 19530。冲突时改 `application.yml` 的 `server.port` 与各连接配置,或改 `docker-compose.yml` 端口映射。

### Q7: 登录 401 / token 失效
token 存 Redis,TTL 默认 720 分钟。过期重新登录。清空全部 token:`docker exec -it pomelo-redis redis-cli FLUSHDB`。

## 10. 停止与清理

```bash
# 停止应用:Ctrl+C(前台)或 kill 进程

# 停止基础设施(保留数据)
docker compose stop

# 彻底删除容器 + 数据(慎用,知识库向量与 MySQL 数据全丢)
docker compose down -v
```

本地上传的文件在 `./data/uploads/`,可按需清理。
